### Fixed

- **One ZWO camera the SDK cannot read no longer blocks a camera saved with an explicit `cameraId` from connecting** (AlpacaCore, issue #1056; `zwo_sdk_wrapper.cpp`, `zwo_camera_identity.h`, `zwo_camera_driver.cpp`, `zwo_switch_driver.cpp`): `ASIGetCameraProperty` answering `ASI_ERROR_CAMERA_REMOVED` for one slot threw away the whole enumeration, so a healthy camera that worked on 4.2.0 failed to connect. An unreadable slot is now skipped and logged at WARN with its slot index and SDK error name, and the readable cameras connect. `cameraIndex` stays the SDK slot after a skip, so an index-bound camera or ASIAIR dew-heater switch still reaches the same body. When the entry's own camera is the unreadable one, the connect refusal names the slot and the SDK error and says to power-cycle the camera and any hub it powers. Tests: `tests/test_zwo_camera_identity.cpp`.
